# Задание для программиста 1С

Короткое техническое задание. Его можно отправить вашему 1С-специалисту как есть —
он или откажется, или скажет, сколько это стоит. От его ответов зависит этап 4
нашего проекта, но начинать нужно заранее: на этапе 1 данные 1С ещё не нужны,
а спрашивать начните сейчас.

---

## Часть 0. Что нужно узнать и сообщить нам (это бесплатно, 10 минут)

1. Конфигурация: **УНФ / Бухгалтерия / УПП / «Автосервис» / что-то своё** — название
   и версия (Справка → О программе).
2. Платформа 1С:8.3 — какая версия.
3. База **файловая или клиент-серверная** (SQL).
4. Опубликован ли на сервере **веб-сервис / HTTP-сервис**, и есть ли человек,
   который умеет его опубликовать.
5. Снимается ли конфигурация **с поддержки** — можно ли её дорабатывать.
6. Есть ли **тестовая копия** базы, на которой можно пробовать, не рискуя рабочей.
7. Каким документом у вас оформляют **списание материалов** сейчас
   (Требование-накладная, Списание материалов, Отчёт о розничных продажах, своя
   обработка)?
8. Есть ли в 1С **справочник работ/услуг** и цены на них, или прайс живёт в Excel.

---

## Часть 1. Выгрузка номенклатуры (обязательный минимум)

**Цель:** наша программа получает справочник материалов и цены, чтобы не вести
второй справочник руками. 1С при этом ничего не теряет — мы только читаем.

**Что выгружать:** справочник «Номенклатура» — только то, что реально может
уйти в малярный цех (по группе, по складу или по наличию остатка — решать вам).

**Состав файла** — одна строка на позицию:

| Поле | Обязательное | Пример |
|---|---|---|
| Код | да | `SE171695` |
| Артикул | нет | `563 SCHWARZ` |
| Наименование (краткое) | да | `Краска MIX 563 Schwarz B 3,5 л` |
| Полное наименование | нет | |
| Единица измерения | да | `шт`, `кг`, `л` |
| Группа / вид номенклатуры | да | `Краски`, `Абразивы` |
| Цена | да | `1250.00` |
| Валюта | да | `RUB` |
| Ставка НДС | нет | `20` |
| Остаток (если нужно) | нет | `12` |
| Пометка на удаление / архив | да | `0`/`1` |

**Формат:** CSV, кодировка UTF-8, разделитель `;`, первая строка — заголовки.
Годится и JSON — как удобнее программисту.

**Куда:** в папку в локальной сети, например `\\server\exchange\1c\to_paint\nomenclature.csv`
(папку для обмена заводит ваша сторона).

**Как часто:** раз в сутки ночью по регламентному заданию. Плюс возможность
нажать кнопку и выгрузить «сейчас» — чтобы после заведения нового материала не
ждать до утра.

**Правила, без которых не заработает:**

- **Код не должен меняться.** Это ключ, по которому мы сопоставляем позиции.
  Если код пересоздают — все наши списания теряют связь с материалом.
- **Удалённые позиции не пропадают из файла**, а помечаются — иначе мы не поймём,
  почему материал исчез.
- Файл выгружается **целиком**, а не «только изменённое». Так проще и надёжнее:
  мы сами сравниваем с тем, что у нас есть.

---

## Часть 2. Если есть HTTP-сервис или OData — вариант получше

Если ваша 1С умеет отдавать данные по запросу (опубликованный HTTP-сервис или
стандартный интерфейс OData), это предпочтительнее файлов: свежесть данных и
никаких «а файл не выгрузился».

**Что нужно:** тот же набор полей, отдаваемый по запросу, с авторизацией по
логину/паролю и фильтром «изменённые с такой-то даты».

**Что уточнить у программиста:** получится ли это без доработки конфигурации, и
если с доработкой — сколько это стоит и не слетит ли при обновлении.

---

## Часть 3. Обратная задача — наши списания в 1С (позже)

Сейчас бланк уходит на склад в PDF, склад выдаёт материал, бухгалтерия переносит
в 1С. Если всё пойдёт хорошо, этот шаг можно автоматизировать.

**Что мы дадим:** файл с тем же составом, что и бланк:
номер заказа, дата, подразделение (малярный цех), склад, код номенклатуры,
количество, единица, кто списал.

**Что нужно сделать:** превратить этот файл в документ списания в 1С, который
бухгалтер потом просто проводит (или который проводится сразу — как принято у
вас).

**Важно:** мы **не** пишем напрямую в базу 1С и не трогаем её структуру. Только
файл или вызов сервиса. Так обновление конфигурации ничего не ломает.

---

## Чего делать не нужно

- Не открывать доступ к файлу базы 1С для внешней программы.
- Не менять структуру конфигурации «под нас».
- Не делать двустороннюю синхронизацию «всё со всем». Только номенклатура
  к нам, списания от нас. Всё остальное — лишний риск.

---

## Что нам нужно получить в ответ

1. Ответы на вопросы из части 0.
2. По части 1: подтверждение, что выгрузку можно сделать, ориентировочная цена
   и срок, согласованные путь к папке и имя файла.
3. По части 2: можно ли, и сколько стоит.
4. По части 3: каким документом оформлять списание и в каком виде он предпочитает
   получать данные.

---

## Приложение: как мы будем это принимать

Наша сторона читает файл и сравнивает с тем, что уже есть:

- новая позиция — добавляется;
- изменилось название, единица, цена — обновляется;
- позиция помечена на удаление — не удаляется, а скрывается из поиска
  (в старых заказах она остаётся);
- код пропал из файла — ничего не удаляем, только показываем предупреждение,
  потому что это почти наверняка ошибка выгрузки.

Все изменения пишутся в журнал: когда, что и в каком количестве синхронизировалось.
